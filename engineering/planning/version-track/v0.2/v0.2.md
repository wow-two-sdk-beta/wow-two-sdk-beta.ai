### Iteration 1 — Queued comparisons

- [x] Ability to queue a model × version matrix for a worker
- [x] Ability to sample items by count, seed, tags or ids
- [x] Ability to pin each batch's items, expected answers and scoring
- [x] Ability to pin each cell's prompt row, text, parameters and schema
- [x] Ability to fail a run whose pinned input changed or was purged
- [x] Ability to run queued evals in any host with an opt-in worker
- [x] Ability to claim each run once across instances
- [x] Ability to cancel a run between items and keep its scores
- [x] Ability to fail a run whose heartbeat went stale as orphaned
- [x] Ability to cap models × items per request
- [x] Ability to tell new spend and unpriced items apart in a report
- [x] Ability to upgrade a `003` database without blocking writes

### Iteration 2 — Tenant scopes

- [x] Ability to file calls, sets and runs under a data scope
- [x] Ability to filter inferences, totals and runs by scope
- [x] Ability to reuse a stored answer only within its scope
- [x] Ability to purge a subject's answers within chosen scopes

### Iteration 3 — HTTP API

- [x] Ability to mount the API in any host with `AddAiApi`/`MapAiApi`
- [x] Ability to require `ai.*` scopes per route
- [x] Ability to restrict every read and write to the caller's scopes
- [x] Ability to queue a matrix over HTTP and get `202` with its batch
- [x] Ability to read a report as json, csv or md over HTTP
- [x] Ability to list providers with priced and live models
- [x] Ability to lift the scopes in Development only

- [x] Ability to sample items on `ai eval run`
