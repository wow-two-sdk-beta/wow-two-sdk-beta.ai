# v0.3 — Image inputs

*Last updated: 2026-11-19*

**Status:** 🔄 In progress · **Type:** Feature · **Started:** 2026-11-18 · **Completed:** —

SCFD tags and parses Instagram posts whose event facts (dates, venue, fees) sit in the poster, not the caption; its
Instagram reader still warns that "Image and video text has not been read". Images live privately in SCFD's file
storage, so the host resolves each one to bytes. Contract: `engineering/architecture/contract.md` § Rules, Images.

### Review fix — image fetch allowlist

- [x] The module's own HTTP(S) image fetch reads only hosts listed in `Ai:Module:ImageFetchHosts` (exact or `*.` subdomain entries); empty by default, so no caller with `ai.run` or `ai.evals-manage` can make a host request an arbitrary or internal URL. A host's own `IAiImageResolver` is unaffected; the E2E host lists `localhost` for its poster. Unit tests cover exact, subdomain, case, a metadata address and the empty list.

Use case `ocharo-relevance` on the local bench (AI v0.3, migration `006`), 10 Russian Afisha posts with draft labels (4 close, 2 loose, 4 none), scored on `relevance`. Posts and answers stay in the bench database.

### Provider fix — thinking off per model

- [x] Effort `none` on an Anthropic model sends `thinking: disabled`; when a model answers the 400 that names `between_tools` (Sonnet 5.5), the same attempt goes again once with `thinking: {"type":"between_tools"}` set through the raw request, and the caller sends it first for that model afterwards; no other effort ever takes it. 11 stub-HTTP wire tests (Providers tier 122 → 133).

### Provider fix — schema in the instructions when refused

SCFD's `extract-event` (16 nullable union fields) and `extract-listing` (29) schemas exceed Anthropic's structured-output limits; Haiku 5.5 and Sonnet 5.5 answered every call 400 "The compiled grammar is too large", before any token was billed.

- [x] Ability to retry once with the schema in the system instructions when Anthropic refuses it as too large or too complex ("compiled grammar is too large", "Schema is too complex for compilation"); the retry sends the kind's JSON mode (OpenAI `json_object`, Ollama `"json"`) or no format (Anthropic). Any other 400 fails as before; no OpenAI-compatible wording is matched, as neither its SDK nor its docs name one
- [x] Ability to remember a refused schema per `{provider}/{model}` and schema hash, so later calls skip the refused attempt; it combines with the `between_tools` retry
- [x] Ability to check an answer wrapped in a fence or prose exactly as a structured one: the schema check reads the first fenced or complete JSON object when the whole answer does not parse
- [x] Ability to tell the mode on the attempt's span (`ai.request.schema_mode`: `response_format` or `instructions`, from `AiCallResult.SchemaInInstructions`); the inference log has no column for it, and none is added
- [x] Unit tier 139 → 150, Providers tier 133 → 155 (stub-HTTP wire tests: the refusal retries once, the memory skips it, other 400s and other kinds do not retry, both retries together, JSON mode on the OpenAI and Ollama wire)
