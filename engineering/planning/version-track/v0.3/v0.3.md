# v0.3 — Image inputs

*Last updated: 2026-11-18*

**Status:** 🔄 In progress · **Type:** Feature · **Started:** 2026-11-18 · **Completed:** —

SCFD tags and parses Instagram posts whose event facts (dates, venue, fees) sit in the poster, not the caption; its
Instagram reader still warns that "Image and video text has not been read". Images live privately in SCFD's file
storage, so the host resolves each one to bytes. Contract: `engineering/architecture/contract.md` § Rules, Images.

### Iteration 1 — Contract

- [x] Ability to name an image by public URI or host key (`AiImageRef`)
- [x] Ability to send images with a run (`AiRunRequest.Images`)
- [x] Ability to keep image references on eval items and exports
- [x] Ability to return images from a subject source, source-compatibly
- [x] Ability to resolve private keys through a host's `IAiImageResolver`
- [x] Ability to set how many images a prompt takes (`MaxImages`)

### Iteration 2 — Module

- [x] Ability to fetch public `http(s)` images with size and time limits
- [x] Ability to refuse images over the limits before any call
- [x] Ability to read the media type from the bytes
- [x] Ability to ignore images a text prompt does not take
- [x] Ability to tell cached answers apart by image bytes
- [x] Ability to log each attempt's image count and hashes (`006-image-inputs`)

### Iteration 3 — Providers

- [x] Ability to send Anthropic base64 image blocks
- [x] Ability to send OpenAI-compatible `data:` URL image parts
- [x] Ability to send Ollama base64 message images
- [x] Ability to count image tokens as input tokens

### Iteration 4 — Evals, API, verbs, fe

- [x] Ability to pin each item's image hashes on a queued batch
- [x] Ability to fail a run whose pinned image changed
- [x] Ability to carry images over the HTTP API and the client
- [x] Ability to send images from `ai run --image` and `ai eval add --image`
- [x] Ability to save a prompt's `--max-images` from the verbs
- [x] Ability to type the image fields in `fe-ai/contracts`

### Review fix — image fetch allowlist

- [x] The module's own HTTP(S) image fetch reads only hosts listed in `Ai:Module:ImageFetchHosts` (exact or `*.` subdomain entries); empty by default, so no caller with `ai.run` or `ai.evals-manage` can make a host request an arbitrary or internal URL. A host's own `IAiImageResolver` is unaffected; the E2E host lists `localhost` for its poster. Unit tests cover exact, subdomain, case, a metadata address and the empty list.
